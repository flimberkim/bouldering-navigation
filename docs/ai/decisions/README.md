# decisions/ — 결정 사례 로그

> **적용 범위**: 일반 규칙과 다르게, 하지만 의도적으로 처리한 결정 하나하나를 파일 1개로 기록하는 곳.

## 언제 여기에 기록하는가

- 기존 규칙 문서(`architecture/`, `dto/`, `api/` 등)를 그대로 따르지 않고 의도적으로 다르게 구현했을 때.
- 여러 대안 중 하나를 선택한 이유가 나중에도 궁금해질 만한 결정일 때.
- 재사용 가능한 일반 규칙이 아니라 "이 상황에서는 이렇게 했다"는 구체적 사례일 때 (재사용 가능한 규칙이면 대신 관련 `docs/ai/*` 규칙 문서를 갱신한다).

단순 리팩터링, 오타 수정, 일회성 변경은 기록하지 않는다 — git 커밋 로그가 이미 담당한다.

## 파일명 규칙

`YYYY-MM-DD-짧은-설명-kebab-case.md` — 날짜는 결정이 내려진 날, 설명은 파일명만 보고도 무슨 결정인지 알 수 있게 짓는다.

## 항목 템플릿

```markdown
# {결정 제목}

- 날짜: YYYY-MM-DD
- 관련 커밋: {짧은 해시} {커밋 메시지 첫 줄}

## 무엇을 결정했는가

## 왜 (배경/문제)

## 고려했던 대안

## 영향받은 부분

## 관련 문서
```
